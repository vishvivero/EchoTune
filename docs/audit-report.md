# EchoTune PRD-1 codebase audit

**Audit date:** 18 September 2026  
**Baseline:** `main` at `947ef12b444c6ca93ab9efd98a8a4472bc91c3bf` (EchoTune 7.4.7)  
**Scope reviewed:** 350 tracked paths; 236 Swift files; 115 app Swift files / 31,837 app-source lines; unit/UI tests; Xcode project and entitlements; SwiftPM lockfile; release/update configuration; documentation; all user-facing SwiftUI views and the live `echotune.app` purchase/legal/update URLs.

## Top five things to fix first

1. **Stop writing dictated text to macOS Unified Logging.** Multiple release-path `os_log` calls write full local and cloud transcripts. This defeats the product's privacy promise and can expose sensitive dictation to anyone with log access.
2. **Repair checkout and legal destinations.** The onboarding Buy button opens a live 404 (`/checkout`), while the App Store purchase screen links to live 404 privacy/terms pages. This directly blocks or undermines purchases.
3. **Make direct-sale device limits real.** Polar keys are only validated, never activated against a device allocation. The locally stored fingerprint is not sent to Polar, so the UI's 1-Mac/3-Mac claims are not enforced.
4. **Protect local transcript-derived data.** Transcripts, notes, commitments, window titles and error logs are stored as plain preference values without explicit file protection, retention bounds or a complete erase/export path.
5. **Align product claims with behavior.** The website, Info.plist and docs make contradictory claims about cloud use, screen context, audio retention, prices, OS support and referral rewards.

## What was validated

- The exact main revision and complete tracked tree were read from GitHub and audited locally file-by-file with targeted second passes over authentication/licensing, purchase, storage, cloud provider, update, permission, logging and referral code.
- GitHub Actions run `35131367272` for this exact SHA completed successfully: <https://github.com/vishvivero/EchoTune/actions/runs/35131367272>.
- The repository has 22 test source files. CI builds Debug and runs `EchoTuneTests`; it does not run `EchoTuneUITests`.
- The last three CI runs on `main` are green. Earlier failures remain in history, but are superseded by the passing exact-SHA run.
- The live appcast returned valid signed Sparkle entries for 7.4.7 and 7.4.6: <https://echotune.app/appcast.xml>.
- The live homepage returned HTTP 200: <https://echotune.app/>.
- Live purchase/legal checks on 18 September 2026: `/checkout`, `/privacy`, and `/terms` each returned HTTP 404.
- Polar documents the public customer-portal validation endpoint as safe for clients, so the endpoint's lack of an app secret is not itself an issue: <https://polar.sh/docs/api-reference/customer-portal/license-keys/validate>. Polar separately documents activation as required when device allocations are enabled.
- The audit environment is Linux and has no Xcode/Swift toolchain, so I did not claim a second local macOS build or pixel-level walkthrough. The exact-SHA macOS CI build/test is the executable validation source; the missing UI-test execution is flagged above.

## Immediate-fix decision

No confirmed **critical** issue was found, so this audit does not silently refactor the codebase. The two clearest high-impact fixes should be separate reviewable PRs:

1. remove transcript bodies from release `os_log` calls;
2. replace the dead onboarding checkout route with the canonical Polar storefront path.

All other items remain flagged for owner prioritization as required by PRD-1.
